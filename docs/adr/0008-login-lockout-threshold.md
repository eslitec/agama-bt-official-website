# 後台登入鎖定：20 次 / 2 分鐘，並保留編輯器端的解鎖後門

後台 API 的登入端點對外公開（Apps Script 存取權「所有人」、回應帶 `Access-Control-Allow-Origin: *`，網址又在前端 JS 裡），
所以沒有次數限制等於開放自動化嘗試密碼，而且每次嘗試都消耗專案的 Apps Script 配額 —— 配額耗盡時整個後台會連不上。
這個風險曾經以 `MAX_FAILS = 0` 的方式被接受，理由是不想因為自己打錯而被關在門外。

現在改為 `MAX_FAILS = 20`、`LOCK_SECONDS = 2 * 60`，並新增只能在 Apps Script 編輯器手動執行的 `unlockAccount()`：
直接按執行會清掉所有管理者的失敗計數，也可以傳帳號只解一個。

20 次 / 2 分鐘是刻意放寬的門檻：真人連續打錯 20 次的機率趨近於零，但足以讓高速的自動化嘗試撞牆；
就算真的被鎖住，最多等 2 分鐘，或在編輯器一鍵解除。比起「完全不鎖」，這個設定同時解掉了被猜密碼與配額被打爆兩個問題，
又不會重現當初關掉鎖定的那個困擾。

改動需要重新部署 Apps Script（部署 → 管理部署作業 → 編輯 → 建立新版本 → 部署）才會生效。
