# 資料下載改用拖曳控點排序，並在同一顆控點上做鍵盤操作

ADR-0005 的「上移／下移」一次只能和相鄰列交換，30 份文件要把最後一筆搬到最前面得按二十幾次，
每按一次都是一趟 Apps Script 寫入。改成拖曳排序：新增 `reorderDownload` action，
以「插在哪一筆之前」（beforeId）指定目標而非位置編號，這樣別人同時新增或刪除資料時不會搬到錯的位置，
一次拖曳只送一個請求。仍然只能在同一個分類內移動，分類區塊維持連續，順序依然就是試算表的列順序。

只做拖曳會讓鍵盤與螢幕閱讀器使用者完全無法排序，所以同一顆控點同時是鍵盤介面：
空白鍵拿起、上下鍵移動（清單即時預覽）、再按空白鍵放下、Esc 取消，每一步都透過 aria-live 念出目前位置。
鍵盤路徑不是附加功能，是拿掉上下箭頭的前提。

滑鼠拖曳時只畫一條插入線、不即時重排，避免整個清單在游標下跳動；鍵盤模式才即時重排，
因為使用者看不到游標位置，需要直接看到結果。邏輯放在 `src/composables/useSortable.ts`，與資料下載無關，
之後其他清單要排序可以直接沿用。

`admin-api.gs` 保留原本的 `moveDownload`（未再被前端使用），移除它需要另一次重新部署，留著不影響任何東西。
