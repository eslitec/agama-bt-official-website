# 後台擴充資料下載與人才發展：以 ID 欄定位、只貼連結、順序交給試算表

客戶要求後台「除了最新消息，也可以上架文件」，並參考舊站加入人才發展（職缺＋教育訓練，兩者都要能編輯）。

## 決定

- **用 ID 欄定位列，不用列號或自然鍵**。「最新消息」本來就有 `ID` 欄；「資料下載」原本沒有，改由 `setupAdminSheets()` 補上並自動編號。列號會因為別人同時編輯試算表而失效；用「分類＋檔名＋格式」當鍵則會在改檔名時找不到原本那列。
- **「人才發展」是新的工作表**，由同一個 `setupAdminSheets()` 建立並印出 gid。gid 沒填進 `src/config/content-sheet.ts` 時（預設 `-1`），前台 `fetchCareers()` 直接回空陣列、頁面顯示空狀態，不會因為少一個工作表就壞掉——與通過驗證業者（ADR-0001）採同樣的降級方式。
- **順序沿用試算表的列順序**，後台只在同一群組（資料下載是同分類編號、人才發展是同類型）內調整順序，分類區塊因此維持連續。不另外做排序欄位，維護者在試算表上看到的順序就是網站上的順序。（當初的「上移／下移」已由拖曳排序取代，見 ADR-0009。）
- **一律只貼連結，不做檔案上傳**。Apps Script 網頁應用程式接收檔案要處理 base64 與雲端硬碟權限，維護成本高；客戶現有流程本來就是把檔案放雲端硬碟再貼分享連結。
- **樣式抽成 `src/styles/_admin.scss`**（`.admin-list`／`.admin-table`／`.segmented`／`.badge`／`.admin-edit`），三個列表頁與三個編輯頁共用，各頁只在 scoped style 覆寫欄位數不同的 `grid-template-columns`。後台分頁從 2 個變成 4 個之後，`.admin-tabs` 改成窄螢幕可左右捲動，否則 320px 會把整頁撐寬。
- **驗證規則在 `admin-api.gs` 與 `src/api/admin-mock.ts` 兩邊各寫一次**，維持既有做法：模擬後台要能在沒有網路後端時重現同樣的錯誤代碼與訊息，`tests/unit/admin-content.spec.ts` 測的就是這份規則。
